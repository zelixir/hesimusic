> 审计对象：海瑟音乐无缝循环（A/B 窗口、进入/退出、三阶段 prelude/loop/tail、试听与确认）
> 设备：OnePlus 8T（b1e84dad），Android 14，静音、解锁
> 方式：真机点击 + uiautomator dump + 截图 + 应用调试口 /state、/debug/preview；先记录现象，实现只用于解释
> 版本：审计期间设备被多次更新，证据按构建分段（见 §2）。2.4.4（1277）完成三阶段与尾奏验证，2.5.1（1278）补上播放页 A/B 文案与显式退出，2.6.0（1293）补上 prelude/loop/tail 阶段文案与 prelude 虚线色带、结果页固定动作栏；历史构建的现象标为“已修复/回归用例”。

## 0. 一句话结论

00028 的主语义在 2.4.4 上已经成立：进循环从 0 起播（prelude）、可以 seek 到 A 之前与 B 之后、尾奏播完能回到 prelude，且不再卡死。2.5.1 把 A/B 与退出做成了可读文案；2.6.0 又把阶段做成可读（`前奏/尾奏`）、prelude 色带改虚线，并把结果页六个动作固定到首屏。
所以到 2.6.0，“循环有没有生效、现在哪一段、动作在哪”这三件可感知性的事已经基本解决。剩余最别扭的是：播放页不能就地改 A/B、确认后起点仍是 0（试听位置丢失）、分析一开就暂停主播放、切歌/通知栏的队列与循环状态不一致，以及尾末回绕的 0.9s 冻结/落点偏移（2.6.0 未复验）。本次最别扭的 10 件事见 §6。

## 1. 方法与边界

### 1.1 走法

每条路径都按“真实用户动作”执行：从主页列表长按/点击、播放页按钮、分析页按钮；只有物理上无法点的（精确 seek、秒级采样）才用调试口补测，并在表里注明。

### 1.2 判据

只用常识判据，不拿实现口径自证：

- 位置：显示位置是否等于用户点的位置；跨 B / 回 0 是否符合“一条 0..曲末 的时间线，唯一折返点是 B→A”。
- 出声：/state.playback 的 playing/buffering/playbackState + /state.invariantProbe.writtenFrames 增长。
- 状态：/state.loop 的 claimed/claimActive/phase/timelinePhase/window/intent。
- 可见性：界面上是否有一眼能看懂的 A/B、阶段、循环是否生效的文案/图形。

### 1.3 未做/做不了的

- 实机锁屏未做：设备 deviceHasKeyguard=true，无法确认是否设了 PIN；为避免把用户手机锁死，路径 3 用“HOME 后台 5s + 通知栏媒体控制”覆盖，锁屏结论标为部分验证。
- 内容真值本轮未采信：尾奏卡死使“tail→回 0”路径在 2.4.2/2.4.3 不可达；对 A 交界做了一次 tap 与源解码互相关，峰值仅 0.32，未收敛，不作为结论。建议修复后用场景套件 #20/#21/#23 回归。
- 2.4.4 尾奏回绕只做了状态与时间轴采样（见 §2.4），没有做听感/内容比对。

## 2. 版本与语义基线（关键：不要把历史现象当现存问题）

### 2.1 目标语义（00028 用户已确认）

    进无缝循环              -> position=0, phase=prelude
    prelude 播到 A          -> 进入 loop（继续，不跳）
    loop 播到 B             -> position=A（无缝折返）
    loop 中 seek 到 A 之前  -> prelude（可听前奏）
    loop 中 seek 到 B 之后  -> tail（可听尾奏）
    tail 播到曲末           -> position=0, phase=prelude

一句话：整首歌是一条 0..曲末 的时间线，唯一折返点是 loop 阶段走到 B 时回 A。

### 2.4 2.4.4 尾奏复验（可靠数据）

    歌 41126，A=23.301s，B=261.457s，时长 284.865s
    seek 275000 -> tail
    275.0 → 284.865：playing=true，buffering=false，phase=tail，claimed=true，intent=41126 全程不变
    284.865 处位置冻结约 0.9s（playing 仍 true）
    随后回 prelude，displayUs≈2.037s，timelineUs 的 local 部分≈48.85s
    播放位置从 284865 直接跳到 2129ms，之后正常前进

结论：

1. 卡死已修：不再 buffering、不再永久停在 131558，符合 1277 的修复目标。
2. “回 0”不干净：用户看到的是回到约 2 秒，不是 0；曲末还有约 0.9s 的冻结（听感上可能是静音停顿）。这两点建议作为 2.4.4 的回归项（displayUs 应为 0 附近，尾末不应有可感知停顿）。
3. claimed 与 intent 在本次受控序列中全程保持；lead 提到的“seek 后 claimed=false / intent 变别的歌”在受控序列中未复现，更可能是并发操作/另一条审计线在动设备导致（见 §1.3 与设备锁说明）。

## 5. 横向问题（比单条路径更值得先修）

### 5.1 状态可见性：2.6.0 已解决（阶段 + A/B + 退出）

**2.5.1**：时间行下方新增“无缝循环中 · 00:23–04:21”，右侧新增“退出无缝循环”（docs/journey/prelude-2.5.1.png）；A/B 与退出已可读。

**2.6.0（当前，已复验）**：
- prelude：状态行“无缝循环中 · 前奏 · 00:23–04:21”，色带虚线/淡（docs/journey/phase-prelude.png）；
- loop：状态行“无缝循环中 · 00:23–04:21”（无阶段词），色带实线（docs/journey/phase-loop.png）；

**结论：状态可见性（“循环生效了吗/现在哪段”）可以结案。** 剩余的小缺口是 A/B 数值只是文本、不能点开编辑（见 5.3），以及结果页/播放页两处“退出无缝循环”是否同一语义（本次未点验结果页的退出）。

建议：把 A/B 文本行做成可点开编辑；其余无需再加视觉元素。

### 5.2 队列不一致：同一个“下一首”有三种行为

| 进入方式 | queue | 下一首行为 |

### 5.3 调参必须离开播放页，且编辑不落地

- 播放页没有 A/B 编辑；唯一入口是长按歌曲 → 无缝分析（会暂停主播放）。
- 编辑后返回不确认 = 静默丢弃；没有“未保存”标记。
- 建议：播放页直接支持长按/点标记进入编辑；分析页返回时提示“放弃修改？”。

### 5.4 确认的副作用没有在按钮上体现

“确认并保存”实际做了：保存窗口 + 回主页 + 从 0 起播 + 队列=1。按钮文案只说了“保存”。建议拆成“保存并循环（从 A）” / “保存并从头播放” / “只保存”。

### 5.5 分析打断播放

打开分析页立即暂停；分析中不能继续听；返回要等分析收尾才恢复。对“我只是想调一下 A”的用户，这是最反直觉的一步。

### 1. 尾奏终点卡死（2.4.2/2.4.3 严重；2.4.4 修复；2.5.1 未复验尾末）

## 7. 建议的修复顺序（按体验收益/成本）

1. 播放页就地编辑 A/B + 未保存提示——把“回主页长按→分析（暂停）→改→返回丢失”的 5 步绕路变成 1 步。

3. 确认时给起点选择（从 A/从头/当前）——2.6.0 实测确认后 pos=15904ms（不是 0），需要明确这是“沿用当前位置”还是“应从 0”。
4. 分析不打断播放（或提供继续播放）——解决“一开分析就静音”。
5. 长窗口降级提示 + 极短窗口警告——边界可感知。
6. 通知栏/锁屏补 loop/phase——外部控制一致性。
7. 尾末回绕回归（displayUs→0、无 0.9s 冻结；2.4.4 已见，2.6.0 未复验）。
8. 主页 ∞ 徽标区分“有结果/正在循环”。
